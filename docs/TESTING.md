# Release validation

Bifrost releases use a compile-first validation policy. Real mod-stack compatibility is tested after a Workshop build is available because those combinations cannot be represented reliably before publication.

## Required before publishing

- Workbench script validation completes with zero Bifrost script errors.
- Game scripts contain no eager non-constant class-level static initializers; keep zero/null defaults and construct cached objects or collections on first use.
- The current compile log contains no candidate-caused VM, GUI, replication, or resource errors.
- Static integrity checks find no missing resource metadata, duplicate GUIDs, merge debris, empty files, or unresolved editor attribute classes.
- The release version, changelog, README, source fingerprint, candidate commit, and addon identity agree.
- `Scripts/WorkbenchGame/EnfusionMCP` is absent and no disposable agent-launched Workbench process is left running. Preserve any Workbench session the operator already had open.

## Multiplayer acceptance pass

Run this pass on a dedicated server with a remote Game Master, then reconnect that client for the JIP checks:

- Kill AI, destroy vehicles, and drop disposable inventory, then use `CLEAR GARBAGE`; confirm the server removes only dead AI bodies, destroyed unoccupied wrecks, and engine-tracked loose items. Living or incapacitated AI, player bodies, usable or player-occupied vehicles, non-deletable/blacklisted assets, and the current GM selection must remain untouched. Confirm every client observes the removals and the state remains correct after JIP.
- Select one group and then several groups, toggle `[ ] LOOP ORDERS`, and confirm the native cycle state repeats the placed waypoint chain, displays `[X]` on the remote GM, and remains correct after JIP.
- Edit a waypoint's `Completion Radius`; confirm the white completion circle changes to the same distance, server AI completes at that boundary, and the value/circle survive JIP. Repeat once for `Approach` and confirm the server uses the selected movement mode.
- Configure a Loiter/Gun Run FX, enable continuous fire, close Properties, and confirm the deployed pass retains every fire setting on the server and remote client.
- Open Effects > Units without search and confirm `Animations FX` and `Arsenal Access` are adjacent and remain visible under every faction filter. Confirm Arsenal Access appears as a script/system entry rather than an arsenal crate. Place it on a world prop and a vehicle; each must show `Open Bifrost Arsenal` above the selected surface, open the Bifrost arsenal from one F press, hide that world interaction prompt while the dialog is open, remain usable by remote players after the vehicle moves, reject duplicate placement, and preserve the interaction after JIP. Deleting the target must also remove its attached access script.
- As a non-GM remote client, verify Arsenal Access opens `BIFROST ARSENAL` on the GRS studio surface with `SOLDIER / GUNSMITH / KITS / SETTINGS` tabs, Bifrost accent colors, and the visible `SPONSORED BY` GRS logo. The live world and first-person weapon must remain outside the preview world, and the interaction prompt must disappear while the menu is open.
- In both player Arsenal Access and GM right-click `Edit Loadout`, overflow every Soldier list, the Gunsmith hardpoint rail, the horizontal candidate strip, and the Kits list. Confirm each list has a reachable scrollbar, wheel input moves only the list under the cursor, and the horizontal strip reaches both ends. LMB drag must rotate the operator or staged weapon, RMB drag must pan, and the wheel over open stage must zoom.
- Select each equipped primary, secondary, and launcher in Gunsmith. Confirm the camera glides to the weapon and selected hardpoint, only native-compatible attachments appear, changing an attachment updates the staged model and hardpoint label, and returning to Soldier restores full-character framing. Empty equipment slots must not flash or steal focus.
- On a dedicated server with one remote client and one JIP client, equip, clear, mount an attachment, wear the draft, enable and disable `APPLY CHANGES ON CLOSE`, save/load/rename/delete a kit, and exercise undo/redo. Confirm the server rejects an invalid target, oversized or incomplete kit stream, non-GM edits of another character, and remote applies outside an active Arsenal Access radius. Successful changes must replicate to every client and survive JIP.
- Confirm legacy GRS kit import is copy-only: imported kits appear in the shared Bifrost bank while the original GRS profile files or console rows remain intact.
- Click Animations FX and confirm its catalog row remains visibly armed with the accent arrow, accent label/icon, and `SELECT AI` status until an AI is selected or targeting is cancelled. Place it on an AI, verify every listed native animation can be selected and is visible on all clients, then enable `Leave when threatened` and drive the AI to alerted state.
- Ctrl-click a group without dragging and confirm native toggle selection still works; then Ctrl-drag it onto a trigger and verify the white line appears only after the drag threshold.
- Open a trigger and verify the larger Bifrost `SETUP / UNITS / FINALIZE` flow, conditional timer/action rows, and live Finalize summaries. Confirm every wrapped description expands its own option row without clipping or overlapping the next option. A close request from Setup or Units must route to Finalize; only `APPLY & CLOSE` may commit. Confirm a newly placed trigger is disarmed and the Stage Hidden warning is visible before applying.
- Configure staged spawn plus queued orders, activate/deactivate the trigger, and verify ellipse/rectangle areas, Present/Not Present, dynamic faction subjects, synced leader/any/all ownership, Countdown, Timeout, repeat cooldown, and Once state on the remote client and after JIP. Confirm dead units do not satisfy Present and a Once trigger remains active after its condition becomes false.
- Ctrl-drag AI groups to a trigger and exercise Linked Only, Stage Hidden, and Ambush Hold. Delete the unfired trigger after staging: every hidden group must return at its recorded transform, held groups must regain their prior fire state, and no pending trigger action may execute. For a repeat trigger, Ambush Hold must re-arm only after the activation condition clears.
- Open each custom Properties view and click the obscured world and menus; confirm the modal consumes those inputs, closes cleanly, and cannot leave an invisible input blocker behind. While trigger properties are open, floating utility panels must be hidden; after close/cancel/fallback, each must return to its exact prior visibility. Verify the trigger uses the Bifrost Properties layout rather than the legacy native form.
- Open the Forces Command picker at each supported UI scale, confirm the right-mouse-button glyph and `CHOOSE FACTION` stay inside the header, assign arbitrary available factions to all four watch slots, replace one slot, and confirm the selection remains stable for the session.
- Exercise the improved right-click Watch menus for units, groups, and triggers; confirm labels remain inside their panels at the supported resolutions and every long list remains scrollable.
- Open EDIT > PLAYERS as a remote Game Master, right-click a player row, and choose `Mark for Teleport`. Right-click empty ground and choose `Teleport Marked Unit Here`; confirm the server moves that exact player while preserving facing, every client observes the move, and the final transform remains correct after JIP. Confirm a limited or non-GM client cannot invoke the server mutation.

## After publishing

Test the changed features with representative third-party mods and confirm the combined Game module compiles without `Too many instructions per function`. Record reproducible failures for the next correction. Post-publication compatibility testing is not a blocker for publishing a compile-clean candidate.
